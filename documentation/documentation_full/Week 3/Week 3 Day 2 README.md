# Quest Log Day 7 — Speed Quest

---

## Objective

The objective for the day was to complete the Speed Quest using the most basic wall-follower code that could work reliably. Our minimum speed target was 1.0, and after reaching that speed, we planned to try increasing it to 1.6. Reaching the higher target would allow the team to earn two coins.

---

## Test Plan

We began with the most basic wall-follower approaches and divided the controller preparation among the team. Zwae worked on the bang-bang controller, Oscar worked on follow the gap, and Arya worked on the PD controller. The plan was to compare the controllers during testing and determine which one worked most reliably at higher speeds.

If the bang-bang controller worked, we planned to use bang-bang only and follow the KISS principle. A simple controller would be easier to tune, explain, and debug during the limited testing time. More complex controllers would only be used if they produced a clear improvement.

---

## Results

The team achieved a maximum speed of 1.2 and earned one coin. This exceeded the minimum target of 1.0, but we did not reach the stretch target of 1.6 or earn the second coin. Because the full goal was not completed, we planned to continue working on the Speed Quest the following day.

---

## Testing Process

The trials were much harder to finish than we thought and took too much time. Switching our rotations and timing helped because we had more time to prepare and make sure our code worked before going downstairs. While downstairs, we also had enough continuous time to test the code and make adjustments before completing a trial.

However, the new system also created a challenge. We did not have time for as many trials because we had to wait while the other teams completed their turns. This made each testing opportunity more important and increased the need to arrive with code that had already been reviewed and prepared.

---

## Next Steps

During the next session, we will continue from the achieved speed of 1.2 and try to improve the controller toward 1.6. We will also work on optimizing our preparation and testing time so that fewer minutes are spent fixing preventable setup or code problems during our assigned rotation.
